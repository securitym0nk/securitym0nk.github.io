Git Tutorial

What is Git ?

According to Wiki, here is the defination:-
Git is a version control system (VCS) for tracking changes in computer files and coordinating work on those files among multiple people. 
It is primarily used for software development, but it can be used to keep track of changes in any files. 
As a distributed revision control system it is aimed at speed, data integrity, and support for distributed, non-linear workflows.

You can read more about on Git on Wiki.

Source: https://en.wikipedia.org/wiki/Git


It was first developed for Linux but now you can use Git on Windows too.
You can Download Git, just by a simple on Google.com
Mostly Git download pages will detect the right Version of Git for you, Go ahead and Download.
Once the setup file is downloaded you can start by double clicking on it.
Now mostly we will keep the installation with default setting, unless we know what exactly changes we need to make.

Once Done then we are good to go.

Now you have seen how to store and create files in Git. So lets Understand the Work Flow of Git.


Work Flow Of Git.

In a layman's defination Git Works in Following statges:

Working_Copy > Staging_Copy > Commited_Copy

Stage 1:
When we first start by creating a simple file in a Git Directory then its on stage on that is Working Copy.

Stage 2:
Once we are done with the file and issue this command 'git add .' or 'git add file_name',
then we are sending all the files to Second Stage.
Please note in this Stage althoug we have added all the files but Git is not Keeping track of file changes.

Stage 3:
Once we have added all the files to Second stage then only we can Ask to Commit all the files.
Now Git has added files to keep track of it.

We can better understand by seeing following Set of Command:

we already have one file in this folder, so lets create few more file to get better understanding of Git workflow:

Now lets add second_file to Second stage by entering following:

Lenovo@avinash MINGW64 ~/Desktop/gitproject (master)

Here we are leaving third_file.

Now lets see the Git status:

Now we can see that the third_file is on Untracked files category which is our working_copy area. In this area any changes we made will not be tracked.
And second_file is on staging area we can get this by this message 'Changes to be committed'. In this area all the changes we made will be tracked.
And if we see Git Log there will be only one file i.e. first_commit. because we have not commited any file other than first_commit.

Lenovo@avinash MINGW64 ~/Desktop/gitproject (master)

Author: SecurityM0nk <education.null@gmail.com>
Date:   Sat Apr 22 21:32:57 2017 +0530

    This is First Commit for tutorial

Lets Summarize this:

Working_Copy Area: -> third_file
Changes made can not be tracked.

Staging_Copy Area: -> second_file
Changes made will be tracked, but not logged in commit.

Commited_Copy Area: -> first_commit
In this Area we have snapshot of all the changes made and also we can go back to the previous one.

Hope now you understood how this work.

How to unstage an file if its on second stage:

Lenovo@avinash MINGW64 ~/Desktop/gitproject (master)
$ ls -l
total 5
-rw-r--r-- 1 Lenovo 197121 63 Apr 23 02:02 first_renamed_again
drwxr-xr-x 1 Lenovo 197121  0 Apr 23 01:16 renamed_file/
drwxr-xr-x 1 Lenovo 197121  0 Apr 23 02:14 Website/

Lenovo@avinash MINGW64 ~/Desktop/gitproject (master)
$ touch file_unstage

Lenovo@avinash MINGW64 ~/Desktop/gitproject (master)
$ git status
On branch master
Untracked files:
  (use "git add <file>..." to include in what will be committed)

        file_unstage

nothing added to commit but untracked files present (use "git add" to track)

Lenovo@avinash MINGW64 ~/Desktop/gitproject (master)
$ git add file_unstage

Lenovo@avinash MINGW64 ~/Desktop/gitproject (master)
$ git status
On branch master
Changes to be committed:
  (use "git reset HEAD <file>..." to unstage)

        new file:   file_unstage


Lenovo@avinash MINGW64 ~/Desktop/gitproject (master)
$ git reset HEAD file_unstage

Lenovo@avinash MINGW64 ~/Desktop/gitproject (master)
$ git status
On branch master
Untracked files:
  (use "git add <file>..." to include in what will be committed)

        file_unstage

nothing added to commit but untracked files present (use "git add" to track)

Here you have successfully staged and unstaged a file.
